# Ask Hynoe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a private, page-aware Ask Hynoe assistant that answers from official Hynoe content first, deep-links to exact site sections, and only uses clearly labeled external Minecraft/mod information when official Hynoe knowledge is insufficient.

**Architecture:** Generate a compact static knowledge index from the public Hynoe repository, then run deterministic client-side retrieval for official answers. Add an optional server-side external fallback endpoint later in the existing Cloudflare community backend so provider secrets never enter browser code. The assistant shares the Hynoe Community shell from the Global Chat plan but remains private and isolated from public chat/game state.

**Tech Stack:** Static HTML/CSS/ES modules, Node build script, JSON knowledge index, optional Cloudflare Worker external fallback, Node `node:test`, Playwright browser tests.

**Spec:** `docs/superpowers/specs/2026-10-06-hynoe-global-chat-ask-hynoe-design.md`

## Global Constraints

- Official Hynoe content always outranks external information for Hynoe-specific questions.
- External fallback answers must be explicitly labeled general Minecraft/mod information.
- If no trustworthy answer is available, say it cannot be verified; never fabricate server-specific rules.
- The assistant is private and must never post into Global Chat.
- Do not send the full Hynoe Outpost save; only non-sensitive page/section/room context is allowed by default.
- Bot history stays local to the browser by default.
- No provider secret may appear in static JavaScript, GitHub Pages config, logs, or responses.
- Existing Outpost save/recovery, Hall of Legends opt-in publishing, on-site YouTube embed, Tap Mine, mini-player, and manual-only Help behavior must remain intact.
- Browser-facing assets use release token `20261006e` for this combined release.

## Review Focus

- Ambiguous questions like “how do I get this?” must prefer the current page/Outpost section without confidently inventing missing context.
- Stale/duplicate headings across pages must produce stable ranking and the most relevant deep link.
- Script/style/admin/private content must never leak into the generated knowledge index.
- A failed external provider must return an uncertainty answer, not an empty panel, raw error, or fabricated response.
- User questions containing HTML/script text must render as plain text and never execute.
