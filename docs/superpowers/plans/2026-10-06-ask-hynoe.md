# Ask Hynoe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a private Ask Hynoe assistant that answers from current Hynoe site/server knowledge, links visitors to relevant pages, preserves short follow-up context, records quality feedback, and safely falls back to deterministic retrieval if the model provider is unavailable.

**Architecture:** Build a versioned knowledge artifact from approved Hynoe repository content, then query it from authenticated Supabase Edge Function `ask-hynoe`. Retrieval is deterministic and provider-independent; optional model-backed answering receives only the user question, bounded conversation history, current page path, and top official Hynoe chunks. The UI shares the Global Chat site panel shell but never publishes bot conversations to public chat.

**Tech Stack:** Static HTML/CSS/ES modules, Node.js built-in tests, JSON knowledge index, Supabase Auth/Postgres/Edge Functions, optional server-side model provider.

**Spec:** `docs/superpowers/specs/2026-10-06-site-help-global-chat-design.md` and `docs/superpowers/specs/2026-10-06-site-help-global-chat-self-review.md`

**Depends on:** Global Chat plan Task 3 guest auth/bootstrap and Task 8 shared site-social panel shell. Ask Hynoe can be developed/tested independently behind the same authenticated visitor session.

## Global Constraints

- Ask Hynoe is private; no question or answer is posted to Global Chat.
- Hynoe-specific facts must come from the generated official Hynoe knowledge index.
- Never infer `confirmed live` from release notes that only say `announced`/planned.
- If retrieval confidence is insufficient, answer that the information could not be verified.
- Browser receives no model-provider key and no Supabase secret key.
- Edge Function authenticates the visitor JWT and rate-limits by authenticated user identity.
- Short history is bounded; v1 does not persist full cross-device chat history.
- Global Chat messages are never trusted as knowledge-source content.
- Generated knowledge excludes admin/internal planning/secrets/obsolete relay docs.

## Review Focus

1. Conflicting dated site content -> prefer newer dated official source and preserve rollout-status wording.
2. Prompt injection inside indexed page text or user question -> treat indexed content as data, not instructions; system rules stay authoritative.
3. Undocumented command/reward/version question -> do not fabricate; return uncertainty + nearest useful official links.
4. Model provider timeout/error -> deterministic retrieval fallback still returns useful official Hynoe help.
5. Oversized/recursive history payload -> reject/truncate server-side before provider invocation.

- `supabase/functions/_shared/help-provider.mjs` — provider abstraction and grounded prompt construction.
- `supabase/functions/ask-hynoe/index.ts` — authenticated API endpoint.
- `supabase/migrations/*_site_help_feedback.sql` — feedback/quality schema + RLS/grants.

- `assets/site-social.css` — assistant conversation/source/feedback states.
- `tests/help-index.test.mjs` — generation/chunk structure tests.

## Definition of Done

- Ask Hynoe is visible in the shared site panel and private from Global Chat.
- Answers are grounded in the current generated Hynoe knowledge index.
- Useful official page links accompany answers where applicable.
- Dated/conflicting rollout content is handled conservatively.
- Unknown Hynoe-specific questions produce uncertainty, not invention.
- Provider failure falls back to deterministic retrieval.
- Feedback/unanswered queue works with RLS-protected admin access.
- No provider/Supabase privileged secret is browser-visible or committed.
- Desktop/mobile and known-answer production smoke tests pass.
