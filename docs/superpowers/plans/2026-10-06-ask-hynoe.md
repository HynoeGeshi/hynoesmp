# Ask Hynoe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a private site help assistant that answers from current Hynoe SMP site knowledge, returns useful source links, keeps short follow-up context, falls back deterministically when no model is available, and never blocks or contaminates Global Chat.

**Architecture:** Build a repository-generated Hynoe knowledge artifact from allowlisted site files, retrieve relevant chunks lexically/fuzzily on the server, and expose one authenticated Supabase Edge Function `ask-hynoe`. The function optionally calls a model provider with only bounded Hynoe context and otherwise returns a deterministic grounded fallback; the existing shared site panel renders the private conversation in its `ASK HYNOE` tab.

**Tech Stack:** Static HTML/CSS/ES modules, Node.js built-in test runner, Supabase Edge Functions/Postgres, repository build script, optional server-side AI provider abstraction.

**Spec:** `docs/superpowers/specs/2026-10-06-site-help-global-chat-design.md` plus `docs/superpowers/specs/2026-10-06-site-help-global-chat-self-review.md`

## Global Constraints

- Ask Hynoe is private visitor-to-bot conversation and never posts into Global Chat.
- Hynoe-specific facts must come from the generated approved knowledge source, not unconstrained model memory.
- Indexed sources are allowlisted site/data files; exclude admin, secret/config, old relay setup, stale planning/spec, and build artifacts.
- Retrieval must work without embeddings or a paid model provider.
- Prefer newer dated content when sources conflict.
- Never claim “confirmed live” from release-note wording alone.
- Never fabricate commands, rewards, version numbers, rollout state, or unsupported server behavior.
- Browser receives no provider credential or Supabase secret key.
- Question/history/token/rate limits are bounded server-side.
- Global Chat must keep working when Ask Hynoe/model provider fails.
- Visitor/public chat content never becomes trusted bot knowledge automatically.

## Review Focus

- Two indexed pages disagree about a feature/version/date: retrieval/answer layer prefers the newer dated source and surfaces uncertainty if status is still ambiguous.
- User asks for an undocumented server command or reward: bot says it cannot verify instead of inventing one.
- Prompt-injection text inside a source page or visitor question asks for secrets/system prompt: answer layer ignores it and exposes no secrets/internal instructions.
- Provider times out/errors: deterministic fallback returns useful matched Hynoe content and the panel remains usable.
- Follow-up history is oversized or contains malformed roles/content: server truncates/rejects safely and does not forward unbounded text to a provider.
